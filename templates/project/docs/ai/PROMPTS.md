# Reusable Prompt Patterns

This is a curated set of repeatable interaction patterns, not a transcript archive or prompt graveyard. Remove patterns that are unmaintained, redundant, or cannot be validated. Architecture and other durable knowledge must remain in their dedicated documents, never only inside a prompt.

## Pattern format

### Pattern name

- **Purpose:** The repeatable engineering outcome this pattern supports.
- **When to use:** Preconditions and unsuitable cases.
- **Expected inputs:** Required files, facts, task scope, and constraints.
- **Prompt pattern:** Provider-neutral instructions with explicit placeholders.
- **Expected outputs:** Artifacts, format, and boundaries.
- **Validation:** Tests, review, source checks, or acceptance criteria.
- **Provider-specific notes:** Include only when necessary; label the provider and explain why the difference cannot remain neutral.
- **Last validated:** Date and context of the most recent successful review.

## Patterns

Add a pattern only after a recurring use case exists.
