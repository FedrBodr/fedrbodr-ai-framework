# Implementation Plans

An implementation plan translates one approved specification revision into small, testable, reviewable steps. It does not change requirements or architecture silently. If implementation invalidates the design, return to specification review and approval.

## Plan header

- **Specification:** Link and approved revision.
- **Risk classification:** Low | Medium | High, with rationale.
- **Owner:** Person or team.
- **Dependencies:** Required prior work or environments.
- **Completion evidence:** Evidence required for the whole plan.

## Task template

### Task N — Reviewable outcome

- **Requirements:** Specification requirement identifiers addressed.
- **Files:** Expected files to create or change.
- **Preconditions:** Required state, decisions, or test baseline.
- **Test first:** Failing test or other initial evidence for the required behavior.
- **Implementation:** Smallest coherent change, without unapproved design expansion.
- **Verification:** Exact tests, checks, review, or inspection to perform.
- **Evidence retained:** Relevant result, report, log, or link to preserve.
- **Done when:** Observable task-level completion criteria.

End the plan with explicit checks for full acceptance-criteria coverage, specification compliance, engineering-dimensions review, documentation updates, unresolved risk, and final completion evidence.
