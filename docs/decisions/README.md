# Architecture Decision Records

Architecture Decision Records (ADRs) capture significant, durable choices affecting the framework. Use a numbered, descriptive file name such as `0002-example-decision.md`. Do not rewrite accepted history to hide a change; add a superseding ADR and link both records.

Each ADR contains:

- **Context:** the problem, constraints, and relevant alternatives.
- **Decision:** the chosen direction and its scope.
- **Consequences:** benefits, costs, risks, and follow-up work.
- **Status:** Proposed, Accepted, Deprecated, or Superseded. A superseded record links to its replacement.
