# Глоссарий

[English source](../GLOSSARY.md) | Русский

> **Статус перевода:** актуален. Каноническим является [английский оригинал](../GLOSSARY.md). Английские термины сохранены для однозначного поиска по framework.

**AI provider — AI-провайдер** — hosted service или local runtime, предоставляющий model inference и связанные возможности. Он заменяем и не является авторитетным хранилищем проекта.

**AI agent — AI-агент** — ограниченный программный участник, который использует модель, переданный контекст и инструменты для выполнения задачи. Его результат не считается доверенным до прохождения валидации процесса.

**AI-first engineering** — инженерная работа, изначально спроектированная для эффективного сотрудничества людей и AI при явной спецификации, governance, quality controls и ответственности.

**Durable knowledge — долговечные знания** — проверенная проектная информация, сохраняемая между сессиями, участниками, инструментами и провайдерами в авторитетном Git-tracked артефакте.

**Ephemeral context — временный контекст** — разговоры, промежуточные рассуждения, tool output или session state, не являющиеся авторитетной записью проекта.

**Source of truth — источник истины** — назначенный авторитет для разрешения конфликтующей информации. В framework переносимые инженерные знания представлены Git-tracked артефактами.

**Provider-neutral core** — долговечные знания, процессы и основные шаблоны, которым не нужны закрытый формат, состояние или поведение одного провайдера.

**Provider adapter** — тонкая tool-specific точка входа, которая находит provider-neutral инструкции и сопоставляет integration behavior, не копируя проектные знания.

**Workflow — рабочий процесс** — последовательность инженерных действий с определёнными входами, выходами, обязанностями, gates и evidence.

**Orchestration — оркестрация** — координация шагов workflow, skills, agents, tools и handoffs. Может быть ручной или автоматизированной и отделена от durable knowledge.

**Skill — навык** — переиспользуемый метод выполнения класса инженерной работы без фактов конкретного проекта.

**Engineering dimension — инженерный аспект** — сквозная область, например безопасность или reliability, применяемая к требованиям, дизайну, реализации и evidence.

**Verification evidence — свидетельства верификации** — актуальные проверяемые результаты, подтверждающие или опровергающие утверждение: test output, review findings, measurements, logs или acceptance checks.

**Context Efficiency — эффективность контекста** — практика сохранения высокосигнального контекста и доступа к raw evidence при уменьшении повторяющегося или малосигнального материала.

**Project memory — память проекта** — поддерживаемая часть durable knowledge, нужная для понимания, эксплуатации и продолжения проекта; не стенограмма всех взаимодействий.

**Engineering Knowledge Lifecycle** — создание, валидация, одобрение, использование, обновление, deprecation, архивирование, retrieval и восстановление производных представлений знаний.

**ADR — Architecture Decision Record** — версионируемая запись контекста, решения, последствий и статуса архитектурно значимого выбора.

**Reference implementation — эталонная реализация** — реальное внедрение для демонстрации и оценки практик. Оно даёт evidence и примеры, но не определяет framework автоматически.
